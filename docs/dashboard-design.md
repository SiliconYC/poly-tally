# 数据看板视觉升级

## 设计目标

Poly Tally 是代码规模观察工具，不是生产力评分。此次采用暖白底色、墨色文字和克制的青绿强调色，不下载字体，不绘制装饰性假图表，不增加外部依赖。

- 清晰导航与紧凑的全局筛选栏之后，突出一个“当前存量”主指标。
- 六个指标切换按钮整合为主图与范围导航之后的次级条带，不再用六张同权卡片挤占主图位置。顶部指标下拉框依然可以直接切换。
- 仓库图层使用原生 `<details>` 折叠。按钮、标签、各仓库颜色、键盘访问和 Shift 独看行为全部保留；折叠本身不会改变纳入统计的仓库。
- 桌面端月度变化与语言构成并排。语言长列表独立滚动，不删除小语种，也不合并为无法核对的“其他”。
- 仓库表格保留搜索、排序、当前列表合计及 CSV 导出。窄屏横向滚动，不暗中隐藏数据列。
- 针对紧凑桌面、平板和手机设置断点，保留减少动态效果偏好与清晰的键盘焦点。

## 保持不变的约定

不修改采集器、数据、发布工作流和统计逻辑。存量对齐、未知期初、部分月份比较、筛选、图表范围刷选、键盘与指针交互、CSV 转义、私有数据边界均沿用原实现及测试。图表模块只修改配色常量；现有 DOM 标识符与事件绑定保持完整。

## 验证

执行：

```sh
node --test web/*.test.mjs scripts/*.test.mjs
node scripts/build-site.mjs
```

新增 `web/layout.test.mjs` 检查 DOM ID 唯一性、应用中写明的元素查找标识、指标与排序控件完整性、折叠后的图层控件，以及未知期初等统计说明。它们是结构测试，**不能代替真实浏览器的视觉与交互验收**。

浏览器验收应覆盖：桌面与 390px 手机截图；清空仓库选择及重置；高级筛选；指标切换；图例展开与显隐切换；月度点击缩放；日期范围刷选；语言筛选与恢复；表格搜索、排序及导出；键盘焦点；页面横向溢出。应检查最终发布版本，而不只检查源文件。

## 发布资源一致性修复

2026-10-21 候选发布后的真实云端浏览器验收发现：HTML 已出现新标题，但计算样式中的 `--bg` 仍为旧值 `#f8fafc`，品牌和导航因此使用旧样式挤在一起。普通刷新与强制刷新均未消除，说明仅看源码或构建成功不足以证明线上样式一致。

构建器现在对 CSS、入口脚本及完整本地模块图计算统一内容摘要，生成带摘要的文件名，并重写 HTML 和模块内部的相对引用。任一界面资源改变都会产生新 URL，避免新 HTML 沿用旧缓存资源；统计 JSON 不参与摘要，也不修改数据路径。源目录保持普通文件名，便于本地开发。新增回归测试覆盖嵌套导入、动态导入、数据引用不变、同内容摘要稳定、样式变化导致整体版本改变及旧产物清理。

此措施针对已获取新 HTML 的访客。浏览器若仍持有旧 HTML，仍需取得新页面；构建器不能替代托管平台的 HTML 缓存策略。

## 首屏层次复验

实际 1165 × 747 桌面截图显示，首轮虽降低了卡片权重，但六指标条带仍使趋势图过低。最终把条带移到主图及范围导航之后，并适度压缩桌面标题区和主指标区留白，保留大数字字号；首屏优先呈现主指标与真实走势。结构测试锁定这一内容顺序。
