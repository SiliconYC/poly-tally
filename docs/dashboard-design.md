# 数据看板布局

## 当前设计

React 迁移保留工程优势，界面遵守“少即是多”。布局参考 [Tremor Overview](https://overview.tremor.so/) 的数据层级和留白，继续复用 shadcn/ui、Recharts 与 Tailwind，不新增大型 UI 或图表体系。

- 只有一重 Header：Poly Tally、更新时间和操作。没有宣传标题、工作空间面包屑或副标题。
- 筛选后直接呈现六项指标，用数字层级和明确选中态突出当前指标，不在卡片下重复解释标签。
- 历史趋势是页面主体。图层与快照明细按需展开，键盘教学供辅助技术读取，日期与缩放保持可操作。
- 构成图与净变化是独立分析视图；点击不会筛选整个页面、改变历史窗口或强制滚动。全局筛选只由顶部明确控件修改。
- 不提供周期列表或额外范围选择。变化图的提示只在悬停或键盘浏览时出现，未知值保持未知，不伪装为零。
- 仓库列表默认每页 100 条，可选 200 或 500；搜索、排序、合计和导出覆盖全部匹配记录。
- 运行状态、发布信息及统计口径统一放入默认折叠的“统计说明”。真实采集失败、不完整数据、旧规则和过期数据告警仍保留。
- 非编辑内容不显示 caret、不参与文本选择；输入框和可编辑区域保持原生编辑行为，不拦截浏览器键盘操作。

## 图表浮层

历史图继续使用原有阶梯命中和绘图记忆化。浮层使用 [Floating UI 虚拟锚点](https://floating-ui.com/docs/virtual-elements) 与边界避让，跟随指针，不固定覆盖右上角的最新数据。该依赖也被 Radix 使用，未新增另一套图表引擎。

## 验证

```sh
npm run typecheck
npm test
npm run test:legacy
npm run build
POLY_TALLY_REAL_STATS=/tmp/poly-real-stats.json npm run test:e2e
```

浏览器回归覆盖“点击分析图不改变全局”、100 条默认分页、非编辑 caret、输入框编辑、浮层跟随和边缘避让、默认折叠，以及桌面／手机深浅色、筛选重置、缩放和导出。真实统计模型与私有数据边界保持不变。
