## 为什么这一晚没有完成：责任与边界

本轮主要走授权连接器逐个读取 Git 对象，不是网页爬虫或前端抓取，也不是正常 Git pack 批量传输。
本轮 18 仓固定范围共需 64,759 个合格唯一 blob；临时采集器采用每秒一次起调的保守节奏。
后期实际吞吐约每秒一个已验证版本，因此首次补齐仍是小时级。它不是每次正常增量都必须付出的成本。

**我在这条不合适的大批量传输路径上投入过多，又不断加试验、审查、暂停与恢复，未及时收口。**
存在我方审计长读事务阻塞写入、短运行丢失下一批内存参数等执行问题，均保留证据并恢复，但耗时属于本轮成本，不能归咎用户没有提供 Key。
已经排除的方案也不应继续维护：种子排序的额外 CPU 大于预计节省，不安装；不要继续为连接器临时采集堆复杂调度。

后期大提交补丁试验：11 次 API 读取恢复 704 个唯一版本，按原始 blob SHA/大小验证。
每页执行与校验合计 423.128 秒；首请求到最后验证的实际跨度约 1,259.836 秒，额外时间包含审计、设置、恢复和等待。
这不是全流程明显提速的证明。补丁采集器仍是云端临时实验，**未纳入本仓生产程序**。

## 接手优先路线：保留产品，换合适的传输环境

建议先检查接手电脑或执行环境已有的正常 GitHub 授权，验证一个私有源的只读 Git 读取。
**有正常 Git 权限就优先本仓原有 Native Git 路线，不必继承这套临时连接器调度器。**
不要求用户把 Key 发到聊天里，也不把本次云端缺少批量 Git 授权解释为整个项目必须新 Key。
不得从浏览器会话或连接器提取凭据。若仍只有逐对象 API，先给出预计调用数与时长，不再默默跑一夜。

在已打开的本仓工作区同步 `dev` 后，安装锁定依赖并检查 CLI：

```bash
python -m pip install --require-hashes -r requirements.lock
python -m pip install --no-deps -e .
python -m poly_tally collect --help
```

使用**全新、独立状态目录**重算，不导入旧派生统计；若当前环境已经配置 Git credential helper，可使用已有入口：

```bash
python -m poly_tally collect --git-credential --state /安全目录/poly-tally-fresh --include-private-metrics --private-metrics-output /安全目录/private-metrics.json --output /安全目录/combined-stats.json --refresh
```

上面是接手指令，**本次没有在接手环境运行或证明其授权可用**。先验证权限和覆盖范围，别把命令存在当成已完成。
这次新批次原始对象可作为续接材料，但不能复用旧派生指标；是否迁移对象应按收益和隐私单独决定。
若使用已捕获连接器包，按 [对象包契约](connector-bundles.md) 补齐、重新发现和核对引用，再调用 `scripts/import-connector-bundle.py`；当前包不完整，不可直接发布。

## 最小验收与发布顺序

1. 自动发现覆盖公开/私有及同源归档祖先，保存此次新鲜元数据范围；不手动漏掉仓库。
2. 记录源传输、验证、解析、汇总、发布五段耗时；同一固定输入验证输出等价，别用局部 benchmark 替代端到端。
3. 确认 JSON 等类别为零、同源唯一主导、归档例外、默认分支切换/回退和日周月差分正确。
4. 运行 `python -m pytest -q`、`node --test web/*.test.mjs`、`node --test scripts/*.test.mjs`。
5. 仅导出白名单私有日级指标；不得公开源码、文件路径、提交细节、完整 SQLite 或采集日志。
6. 新鲜读取 `tally-state` 后按当前 SHA 更新，不覆盖并行公开采集成果；完整指标通过校验才按 [外部私有快照发布说明](private-collection.md#显式发布外部完成的私有快照) 显式发布。
7. 确认实际 Pages 部署完成，以真实数据检查桌面/手机、悬停仓库、图表顺序/标签、下拉框和图标对齐。

## 云端断点的可携带性

云端保存了本轮原始对象、调度数据库、冻结规则、测试程序和实验凭证，停止采集时不删除。
它们含私有源代码，**未上传到公开仓库，也未随本文提供**；另一个本地 AI 不能只靠这篇 GitHub 文档直接访问 dot 的云端目录。
因此接手者可以直接采用已提交产品代码并通过已有 Git 授权重新批量获取；不必等待搬运这份临时缓存。
如果确实需要迁移，应先确定安全目的地与访问者，再移交私有包。当前没有完成可携带原始对象交付，也不保证云端目录永久保存。
