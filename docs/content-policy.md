# 统一收录与屏蔽规则

统计对象是仓库中编写和维护的源码、配置与文档。下载依赖、生成产物、运行日志和调试结果不应增加代码量。规则对所有公开、私有仓库相同，修改后重算完整历史，而不是从修改当天开始扣减。

## 为什么不能只改 .gitignore

`.gitignore` 不会删除已经跟踪的文件，也不会改变历史提交中的树。统计直接读取 Git 对象，在 `config.json` 中独立过滤路径；根目录与任意嵌套目录均生效。内容识别在路径过滤之后执行，避免把换了目录的明显产物重新当作源码。

- `rules.exclude`：明确依赖、构建、工具状态与底线项，优先排除，不能被源码保护覆盖。
- `rules.artifact_exclude`：日志、结果目录和报告名称等可能有歧义的产物约定。
- `rules.source_preserve`：为上述歧义规则保留源码、测试、`README`，以及 `docs` / `Docs` / 以“文档”结尾的目录内文本文档；例如 `src/config/performance.json`、`tests/fixtures/expected-report.json`、`docs/log/format.md` 不会仅因名字被删除。文档目录中的机器 JSON 报告仍过滤；内容确为重复运行日志或生成源码时仍由内容策略排除。

不继承各源仓库自己的 `.gitignore`，以免各仓库统计概念不一致。也不修改源仓库的文件、分支或既有专属统计。

## 路径屏蔽

完整模式以 [config.json](../config.json) 为准。

| 类别 | 代表性规则 | 保留的内容 |
| --- | --- | --- |
| 下载依赖 | `node_modules`、`vendor`、`third_party`、`third-party`、`site-packages`、`.yarn`、`.pnpm-store` | 应用自身的 React / TypeScript / Python 源码 |
| 下载的笔记扩展 | `.obsidian/plugins`、`.obsidian/themes` | 正常文档、项目自己的 `src/themes` |
| 构建与缓存 | `dist` / `Dist`、`build` / `Build`、`Intermediate`、`.vite`、`.next`、`target`、工具缓存 | 测试源码、手写 C / C++ / CUDA / Cython |
| 日志与调试 | 日志目录下的 JSON / TXT / MD / HTML / YAML / XML，以及 `*.log` / `*.log.*` | 日志模块、调试工具实现，例如 `tools/log/parser.py` |
| 明确的机器输出 | `*日志.json`、`*缓存.json`、`*历史记录.json`、`*历史记录字典.json`，`trace.json`、`debug-output.json`、`capture.json`、`performance.json`、`*-performance.json`、`*-report.json` | 普通应用 JSON 配置、关卡、词典及测试数据 |
| 机器三维资产载荷 | 蒙皮网格、烘焙动作采样、绑定导出的完整 JSON 结构 | 普通场景配置、关卡数据和资产生成脚本 |
| 结果目录中的数据 | `results`、`reports`、`derived` 内的 JSON / TXT / HTML / SVG，包含子目录 | 同目录内无生成标记的实现脚本；普通 `src/results/index.ts` |
| 工具生成的元数据 | `.cm/stat`、`.cm/项目更新日志.json`、`.cm/模组信息.json` 及缓存命名 | 不一刀切排除 `.cm` 内所有手写配置 |
| 临时与 Agent 遗留 | `.claude`、`.superpowers`、`docs/superpowers`、临时/备份/交换文件、环境文件 | 上述遗留路径之外正式维护的技能、架构文档及版本历史 |
| 压缩与生成源码 | `*.min.js`、`*.min.css`、source map、lock 文件、`*.gen.cpp`、`*.generated.h` / `*.generated.cpp` | 手写源码与依赖清单 `package.json` |

Agent 遗留、Vite、环境文件、日志与临时文件覆盖 [仓库初始化规范的忽略底线](https://github.com/SiliconYC/skill-kits/blob/dev/tenet/tenet-github-repo-init/SKILL.md)。该规范的 `!.env.example` 保留模板；本项目当前语言表不收录 `.example` 扩展名，因此它不进入代码量。

这些名称在统一口径中被视为产物约定，源码与测试上下文会保护歧义名称。新程序宜将机器输出放到 `log`、`results`、`reports` 等目录，而非混入源码。若约定需要调整，应修改全局规则并重算，不能临时针对某个仓库换口径。

## 内容识别

[内容策略](../poly_tally/content_policy.py) 使用确定性的窄规则，不按体积、增长幅度或单个版权声明猜测作者。

- 生成源码：文件前 8192 字符、首个源码语句之前的前导注释中，存在 `Code generated … DO NOT EDIT`、Protocol Buffers 生成头或 `Generated by Cython`。生成器函数和测试字符串中的样例不会触发。Cython 的 `.pyx` / `.pxd` / `.pxi` 源文件正常统计，生成的 C 不重复计数。
- React 分发文件：前导注释同时存在 `@license React` 和 Facebook / Meta 版权声明。普通 React 组件或一般版权声明不会触发。
- Sphinx 文档产物：HTML 文件头有 Sphinx generator 元信息，或同时出现 `sidebar-tree`、至少 10 个 `toctree-lN` 与至少 10 个 `class="reference internal"`。后三重特征来自实际下载的外部 API 导航片段，不因其放在源码目录而计入 HTML 代码。
- 三维数值资产：在 [资产策略](../poly_tally/asset_policy.py) 验证完整的蒙皮顶点/面/权重/骨索引/骨骼关系，或带来源散列与完整运动采样的烘焙清单，或骨骼变换/参考位置/绑定映射的导出结构。不按 `manifest.json` 名称、文件大小或单个 `positions` 字段过滤。实际文件均已找到写入它们的生成脚本；统一口径将这些结构定义为资产载荷，结构本身不能证明所有同类文件都由机器编写。运行时读取资产不使其变为程序源码，生成这些资产的源码仍统计。
- 改名的 TXT / JSON 日志：前 65536 字符、最多 200 行中，至少 8 条非空记录，且至少 90% 是日期时间开头并带日志级别的原始行，或含有效时间字段与级别字段的逐行 JSON。单条 JSON 样例、源码字符串、Markdown 中的长篇日志教程保留。

实际日志常有重复时间、级别、进程或事件字段，规模随运行次数上涨。路径提供第一层证据，内容规则只补充上述强特征。任意命名的普通 JSON、无标记的第三方源码无法仅凭文本可靠推断来源；发现新类型时应采样生成链路，再增加可解释的统一规则。

## 研究与验证

旧速记统计来自 Windows 源目录统计器；版本历史中的规模来自版本打包器先过滤发行目录、再统计与生成文档的链路。两者规则本来就不同，不能拿总数直接校准本项目。这里只吸收通用经验，不移植业务目录、测试、资源主题、全部 JSON 或 Entrepi 的特化排除。

采样确认 Obsidian 扩展、运行规模 JSON、工具缓存、实验对比结果、提取/验证报告、Cython 与 Unreal 生成源码的误计。另有大的首次导入主要是自有业务源码；清理产物后仍应保留这类跃升。

回归用真实 Git 树验证：原规则下日志导入制造飞升；重算后历史代码量恢复为 `1 → 1 → 2`，与独立全量扫描一致，再次同步不重复重算。反向用例保留关卡 JSON、配置、测试、主题、版本文档和正常日志实现。

## 修改与重算

1. 在 `config.json` 修改统一路径规则；修改内容识别语义时同时提升 `规则_类.统计器版本`，避免复用旧解析缓存。
2. 运行 Python / Node 测试，再用已有本地授权重新采集所有仓库。
3. 同一规则版本重建公开提交树与私有日级快照；不把旧口径私有结果混入新总量。
4. 按 [私有采集说明](private-collection.md) 保存脱敏快照并部署 Pages。完整 Git 对象、文件审计和 SQLite 只留在受保护的本地目录。

这里没有平滑、截断跃升、忽略首提交或跨仓库去重。首次完整导入、批量迁移自有源码等变化仍然保留；同一源码出现在多个被纳入仓库中仍会分别计数。
