# 原生 Git 全量重建与增量实测

## 结果

2026-10-22 在本机使用现有 Git 授权，从全新对象目录、解析事实库及统计数据库完成全量历史重建。纳入的 **29/29** 个源仓库全部成功，无缺失同源成员，无失败；普通归档仓库仅保留排除证据。

| 场景 | 实际耗时 | 获取与计算 |
| --- | ---: | --- |
| 完全冷启动 | **539.230 秒（8 分 59 秒）** | 28 次 Git fetch，67,165 次解析，2,589 个提交重算 |
| 固定输入，保留对象和解析事实，清空统计 | **38.967 秒** | 无网络请求、无解析；完整重放 2,589 个提交 |
| 真实新增提交的增量更新 | **21.839 秒** | 仅 2 个仓库 fetch，解析 22 个文件版本，重算 2 个提交 |
| 无变化的下一轮更新 | **15.087 秒** | 28 个非空仓库跳过 fetch；解析、对象读取和提交重算均为零 |

精确机器记录见 [JSON 报告](benchmarks/native-rebuild-2026-10-22.json)。耗时是采集程序实际运行时间，不包含本次开发、代码审查和 Pages 排队部署时间。空仓库仍通过授权分支列表核实，未拿缺失对象当零。

固定输入重放逐仓库比较完整逐提交历史、语言指标及最新文件清单，仅忽略观测时间 `lastSuccessAt`，结果完全一致。完整输入聚合指纹为 `2daa61af8c10fc637b90ee5db225e42a28e93b9af974007e5751c8ca598aa821`。报告中的 34 条状态包括 5 条归档排除记录；29 是实际纳入扫描的源仓库数。三成员同源组折叠后，网页统计项数量更少。

## 耗时分解与证据边界

首次采集的 Git 获取为 `167.071` 秒，历史计算为 `352.797` 秒，其中词法解析为 `302.922` 秒；元数据发现为 `2.099` 秒，导出为 `0.748` 秒。`parseSeconds` 包含在 `computeSeconds` 中，不能重复相加。剩余时间包括分支核对、初始化、汇总及其他程序开销。

固定输入重放使用已验证的本地 Git 对象；其 `fetchSeconds` 仅是本地目标提交存在性检查，不代表网络。暖重算的进程峰值 RSS 为约 115 MiB（macOS 的原始记录单位是字节）。未捕获冷启动峰值 RSS、准确 API 请求数和网络线速字节，不能用对象库磁盘大小替代网络传输量。

此前云端连接器实验在约 48 分钟后仍未完成全部大仓库；本次真实完整采集已经进入分钟级。但两次环境、源 HEAD 和覆盖范围不完全相同，因此不声称受控对照意义上的加速倍数。原生 Git 批量传输使用项目已有后端，本次将其确立为生产更新路径，并完善了跨批次缓存、增量短路、测量和发布流程。

## 后续更新

在仓库根目录运行：

```bash
node scripts/update-local.mjs
```

默认复用 `.poly-tally/local/` 中的原始对象、版本化解析事实和派生历史，只上传验证过的脱敏私有快照并显式触发 Pages；公开数据由 Pages 独立更新。没有新提交时只进行新鲜授权与 HEAD 核对，不重新下载历史。

规则或同源组变更时使用新 `datasetEpoch`，原始对象与适用的解析事实仍可复用，派生统计从零重建。解析器版本或大小上限改变时，相关事实缓存失效。私有对象和完整 SQLite 不进入公开 Git 分支、Actions cache 或 artifact。

固定输入离线校验命令如下；应在没有其他采集进程运行时执行：

```bash
.venv/bin/python scripts/benchmark-native.py \
  --state .poly-tally/local/epochs/source-only-lineage-2026-10-21-v1 \
  --cache .poly-tally/local/cache/private \
  --output .poly-tally/local/warm-report.json
```

本地详细报告包含私有诊断，不应直接公开；已提交的 JSON 报告只保留聚合测量。云端公开定时更新继续运行；私有自动更新需要显式启用受保护的持久 runner，或由本机调用上述更新命令。
